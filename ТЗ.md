# Техническое задание: Помодоро-таймер (React, без БД)

## 1. Общие сведения

### 1.1. Назначение документа
Настоящее ТЗ описывает требования к клиентскому веб-приложению «Помодоро-таймер». Документ служит основой для разработки, тестирования и приёмки MVP.

### 1.2. Цель продукта
Дать пользователю простой таймер по методике Pomodoro: чередование интервалов работы и отдыха с автоматическим переключением этапов и наглядным счётчиком завершённых помодоро.

### 1.3. Область применения
Личное использование в браузере на десктопе и мобильных устройствах. Приложение работает полностью на стороне клиента: без сервера, без регистрации, без базы данных.

### 1.4. Термины и сокращения
- **Помодоро** — один завершённый интервал работы.
- **Этап** — текущий режим таймера: работа, короткий перерыв или длинный перерыв.
- **Цикл** — последовательность «работа → перерыв», после N помодоро — длинный перерыв.
- **localStorage** — клиентское хранилище браузера для настроек, темы и истории.

## 2. Функциональные требования

### 2.1. Рабочий цикл «Помодоро»
- Длительность работы по умолчанию — 25 минут.
- По завершении интервала работы счётчик завершённых помодоро увеличивается на 1 и запускается перерыв.

### 2.2. Короткий перерыв
- Длительность по умолчанию — 5 минут.
- Запускается после каждого рабочего интервала, кроме случая длинного перерыва.

### 2.3. Длинный перерыв
- Длительность по умолчанию — 15 минут.
- Запускается после каждых 4 завершённых помодоро.

### 2.4. Управление таймером
- Кнопки: **Старт**, **Пауза**, **Продолжить**, **Сброс**, **Пропустить этап**.
- Сброс возвращает текущий этап к начальной длительности.
- Пропуск этапа завершает его без увеличения счётчика помодоро и переводит к следующему этапу.
- Отображение времени в формате `MM:SS` с обратным отсчётом.

### 2.5. Счётчик помодоро и авто-переключение
- Отображается число завершённых помодоро в текущей сессии.
- Переключение этапов происходит автоматически по завершении интервала.
- Автостарт следующего этапа: показываем этап готовым к запуску вручную (автостарт не входит в MVP).

### 2.6. Настройки
Минимальный набор:
- длительность работы;
- длительность короткого перерыва;
- длительность длинного перерыва.
- Значения по умолчанию: 25 / 5 / 15 минут.
- Настройки сохраняются в localStorage и применяются после перезапуска приложения; изменение настроек во время активного таймера — на усмотрение реализации (по умолчанию не сбрасывает текущий этап).

### 2.7. Звуковое уведомление
- По завершении любого этапа воспроизводится короткий звуковой сигнал.
- Системные (браузерные) уведомления **не используются**.

### 2.8. История и статистика (localStorage)
- По завершении каждого помодоро в историю добавляется запись: дата/время завершения и длительность интервала работы.
- Экран статистики показывает: число помодоро за сегодня и суммарное число помодоро.
- История хранится в localStorage; предусмотрено ограничение объёма (например, последние N записей) для защиты от разрастания.

### 2.9. Сохранение данных
- Без сервера и БД; всё хранение — в localStorage.
- Сохраняются: настройки, выбранная тема, история помодоро.
- При первом запуске используются значения по умолчанию.

## 3. Нефункциональные требования

### 3.1. Производительность и точность
- Отклонение отсчёта времени от реального — не более 1 секунды на интервал.
- Отсчёт должен корректировать дрейф при сворачивании/неактивности вкладки (пересчёт по системному времени, не по числу тиков `setInterval`).

### 3.2. Совместимость
- Последние версии Chrome, Firefox, Edge, Safari.
- Корректная работа на десктопе и мобильных браузерах.

### 3.3. Адаптивность
- Адаптивная вёрстка от 320 px; удобное управление с тачскрина (крупные кнопки).

### 3.4. Доступность (a11y)
- Управление с клавиатуры (пробел/Enter для старт-паузы).
- Семантические элементы, ARIA-атрибуты для оставшегося времени и статуса этапа.
- Контрастность текста согласно WCAG AA.

### 3.5. Надёжность
- Корректное поведение при перезагрузке страницы: приложение не «зависает» и не теряет сохранённые настройки/историю.
- Защита от некорректных значений localStorage (валидация/фолбэк к значениям по умолчанию).

## 4. Технические требования

### 4.1. Стек
- **React** + **Vite** + **TypeScript**.
- Управление состоянием: стандартные хуки React (при необходимости — контекст для настроек/темы). Внешние менеджеры состояния в MVP не используются.
- Стилизация: CSS / CSS Modules (без обязательной UI-библиотеки).

### 4.2. Структура проекта (ориентировочная)
- `src/components/` — компоненты UI (таймер, кнопки, настройки, статистика).
- `src/hooks/` — например `useTimer`, `useLocalStorage`.
- `src/lib/` — чистая логика переходов между этапами, форматирование времени.
- `src/types/` — общие типы.

### 4.3. Логика таймера
- Источник истины — абсолютное время завершения этапа; оставшееся время вычисляется на каждом кадре/тике.
- Переходы этапов реализуются чистой функцией (легко тестировать).

### 4.4. localStorage — схема данных
- `settings`: `{ workMin, shortBreakMin, longBreakMin }`.
- `theme`: `'light' | 'dark'`.
- `history`: массив `{ completedAt: string (ISO), workMinutes: number }[]`.

### 4.5. Тестирование
- **Vitest** + **React Testing Library**.
- Покрытие: чистая логика переходов этапов, форматирование времени, хук таймера, ключевые сценарии компонентов.

## 5. UI/UX

### 5.1. Экраны
- **Основной:** текущий этап, оставшееся время, кнопки управления, счётчик помодоро.
- **Настройки:** длительности работы и перерывов.
- **Статистика:** помодоро за сегодня и всего.

### 5.2. Состояния интерфейса
- Ожидание, идёт отсчёт, пауза, этап завершён.
- Визуальное различие этапов (работа / перерыв) через цвет и подпись.

### 5.3. Тема и язык
- Светлая и тёмная темы с переключателем; выбор сохраняется в localStorage.
- Язык интерфейса — **русский**.

## 6. Ограничения и допущения
- Нет бэкенда, нет базы данных, нет API.
- Нет аутентификации и многопользовательского режима.
- Нет синхронизации между устройствами.
- Данные привязаны к конкретному браузеру/профилю.
- Считается, что браузер поддерживает localStorage.

## 7. Критерии приёмки

### 7.1. Сценарии проверки
1. Запуск таймера работы и корректный обратный отсчёт 25:00 → 00:00.
2. По завершении работы счётчик помодоро увеличивается на 1, звучит сигнал, запускается перерыв.
3. После 4 помодоро запускается длинный перерыв (15 минут).
4. Пауза/продолжение и сброс работают согласно п. 2.4.
5. Изменение настроек сохраняется после перезагрузки страницы.
6. Переключение темы сохраняется после перезагрузки.
7. История помодоро пополняется; статистика отображает корректные числа.
8. Отсчёт остаётся точным после сворачивания вкладки.
9. Автотесты (Vitest + RTL) проходят.

### 7.2. Definition of Done
- Реализованы все пункты раздела 2.
- Пройдены сценарии приёмки из п. 7.1.
- Проект собирается (`vite build`) и запускается (`vite dev`) без ошибок.
- Нет ошибок типизации TypeScript и предупреждений линтера.

## 8. Приложения

### 8.1. Out of scope (возможные доработки)
- Автостарт следующего этапа.
- Системные браузерные уведомления.
- Расширенная статистика и графики.
- Синхронизация между устройствами, аккаунты.
- Настраиваемая длительность длинного перерыва и правило N помодоро.
